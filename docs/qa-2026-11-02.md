# CRM acceptance verification — 2 November 2026

The deployed CRM health check passed at `https://crm.maxtravel.in`. Anonymous access to work, employee, reporting and audit data and to customer, payment and settings mutations was denied. The deployed authenticated workspace requires existing staff login/MFA, so the following transaction and UI checks used disposable local fixtures with application source matching the deployed CRM.

## Results

All eleven complete UI groups passed: sign-in/MFA, first-time setup, operations, sales, records, customer data, administration, finance, incoming documents, case workflow and reporting.

The workspace audit covered 86 desktop/phone screens and seven daily-work journeys. Case-workflow verification added 48 captures across desktop, tablet and phone widths. The accessibility gate reported zero findings outside its empty accepted budget; no budget was loosened.

The tested operational flow was first contact → permanent case ID → service work → administrator assignment → staff start/wait/resume → submission → return for correction → resubmission → separate approval. Stale settings updates and legacy completion bypasses were denied. Read-only staff lacked write launchers and remained denied by the server.

The reporting browser verified customer statements and balances, supplier statements, due dates, scoped staff/status filters, work and cash drill-downs, Excel and PDF outputs, applied-versus-draft filters, delayed response protection, recoverable errors, read-only export denial and layouts at 1440, 390 and 320 pixels.

Finance journeys exercised receipts, advances and allocation, ticketing, refunds and supplier settlements. Visa checks covered destination/type matching, age at travel, unknown dates of birth, explicit exemptions, appointment prerequisites, India-time editing, retry idempotency and same-name applicant isolation.

## Booking integration

A fresh build of the current booking source was connected to the CRM using actual local HTTP, workers, PostgreSQL, SQLite and signed events. Flight and hotel transactions each produced a permanent case, one receipt and one invoice. Replayed events did not duplicate records; forged signatures were rejected. Customer My trips, CRM online bookings and both cases appeared correctly in desktop/phone browsers. Administrators assigned work on the synced bookings; assigned staff opened the linked booking, started and submitted work; a separate administrator approved it. Staff finance access was denied.

External supplier responses and the legacy gateway capture were synthetic, and mail went only to a disposable local SMTP service. This was not a real PayGlocal payment, live supplier issuance or production customer notification. Temporary PostgreSQL/SMTP containers created for the test were removed afterward.

No CRM application defect was reproduced during these checks. One hotel autocomplete defect was reproduced and corrected in the separate booking repository; its correction passed a fresh build and 48 targeted browser checks.
